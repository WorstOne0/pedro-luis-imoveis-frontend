## 3. Map

### Markers — `src/lib/map_marker.ts`, `src/lib/property_glyphs.ts`

Pins are built as self-contained SVG data URIs: the original coloured disc plus a
dark ring and drop shadow, which they were missing.

- `property_glyphs.ts` is **generated** from `public/property_svg/*.svg`. Don't
  hand-edit; regenerate if the artwork changes.
- Disc colours were sampled from the original `public/*_icon.png`:
  `apartment #e3b775`, `house #e47b7b`, `land #8cda8b`, `shop #8d7adc`,
  `sobrado #7d8fee`.
- The glyph must travel inline — an `<image href>` to `/public` is blocked
  inside a `data:` URI.
- Selection thickens and recolours the ring, never the disc; the disc colour is
  the property type.

### Clustering — `src/app/(home)/_components/use_marker_clusters.ts`

Grid clusterer, no new dependency (`@googlemaps/markerclusterer` deliberately
avoided). Listings project to world pixels at the current zoom and bucket into
70px cells; clustering switches off above zoom 16. Clicking a cluster fits its
members' bounds.

`hasRealPosition()` lives here and is the guard for the `{lat: 0, lng: 0}` data
problem — see §7.

### Toolbar — `src/components/google_maps/index.tsx`

Working: layer **menu** (Satélite com nomes / Satélite / Mapa / Relevo), compass
(resets heading + tilt, needle rotates with the camera), zoom ±, distance
measure, my location, fullscreen.

**Removed**: search, polygon, heatmap, elevation. They had empty handlers.
Restoring them is a small diff.

### Distance tool — `src/components/google_maps/_components/distance_tool.tsx`

Split in three on purpose:

- `useDistanceMeasure(map, isActive)` — state, lives in the parent
- `DistanceOverlay` — polyline + vertices, **must** be inside `<GoogleMap>`
- `DistanceReadout` — the panel, **must** be outside it

Why: Google injects its own containers into the map element at very high
z-indexes, so an HTML panel among the map's children renders but is buried. The
readout also sits at the **bottom** because the site navbar is `fixed` at `z-50`
over the top of the map.

Distances use `geometry.spherical.computeDistanceBetween`, not flat maths.

## 4. District filter ↔ map sync

`src/components/district_polygons/index.tsx` +
`src/app/(home)/_components/searchbar/{store.tsx,components/district_search.tsx}`

**One rule: a district is drawn when selected. Nothing selected means "every
district", so all 32 draw — which is the starting state.**

- Map click selects that district **alone** (replaces); clicking it again clears
  the filter and all outlines return.
- Multiple districts are picked in the multiselect.
- Both write to the same `filter.district: string[]`. The old `useDistrictStore`
  was **deleted** — two stores would drift.
- "All selected" is represented as an **empty array**, not 32 entries, so a
  listing in a district missing from the geo file still appears.

### Name matching — the sharp edge

The geo file and the listing data disagree three ways:

| Polygon | Listing | Difference |
|---|---|---|
| `CANCELLI` | `Cancelli` | case |
| `CANADA` | `Canadá` | accent |
| `BRAZMADEIRA` | `Brasmadeira` | spelling (s/z) |
| `ESMERALDA` | `Esmerald` | trailing letter |

`normalizeDistrict()` strips accents and case; `DISTRICT_ALIASES` names the two
that no rule can derive. Without this, matching was **8/11**; with it, **11/11**.

A polygon click resolves to the *catalogue's* spelling before hitting the API —
that step is load-bearing, not cosmetic. The backend is accent-sensitive, so
`district=CANADA` returns 0 against stored `Canadá`.

**Worth fixing at source:** the geo file is the odd one out, and also carries
`Sâo Cristovão` (should be `São Cristóvão`) plus missing accents on
`Universitario`, `Guaruja`, `Brasilia`. Cosmetic today; will break matching if
listings land there.

## 6. Bug fixed: "Maximum update depth exceeded"

`src/app/(home)/page.tsx`

```ts
const { data: realEstateList = [] } = useApiFetch(...)   // ← the bug
```

The `= []` default builds a **new array every render**. It is in the clustering
effect's dependencies → effect reran each render → `setClusters` → rerender →
new `[]` → infinite loop.

Fixed with a module-level `EMPTY` constant, plus `isSameGrouping()` in the hook
so it only sets state when the grouping actually changed.

Note for future debugging: this only reproduces **with a working Google Maps
key**, because `rebuild()` early-returns before `setClusters` when the map hasn't
loaded.

## 7. Data problems found (not code — needs your attention)

1. **17 of 25 listings have `position: {lat: 0, lng: 0}`.** The legacy import

   Fix by geocoding the addresses; also make the importer leave coordinates
   unset rather than writing zeros.
